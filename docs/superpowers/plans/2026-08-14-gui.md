# The Monolith GUI (SP-GUI) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:subagent-driven-development to implement task-by-task. Steps use `- [ ]`.

**Goal:** A bitmap-only X GUI (dwm + st + dmenu) that runs identically on a 486DX2/8MB and a modern laptop — static, framebuffer-native, zero-dlopen.

**Architecture:** kdrive **Xfbdev** server over the existing vesafb (no DRM), driving a minimal client stack (xorg-proto + libxcb + libX11 + libXext, nothing else). All suckless clients de-Xft'd via ::gentoo `USE=savedconfig` + pinned noxft patches. `startx` is a tiny house shell script; nothing draws at boot. CI proves it via a QEMU `gui` boot-test variant that screendumps and golden-compares.

**Tech Stack:** overlay ebuild `x11-base/monolith-xserver` (lane TBD by G1 recon); ::gentoo x11 libs + dwm/st/dmenu (savedconfig) + font-misc-misc/terminus-font; QEMU screendump + PPM golden compare.

## Global Constraints (from spec §0, §2, §7 — verbatim values)
- ZERO dlopen on the disc. Full Xorg is DISQUALIFIED (it dlopens drivers). X server must be kdrive/TinyX static.
- NO Xft, NO fontconfig, NO freetype ANYWHERE in v1 (hard line). Bitmap core fonts only: `fixed` (misc-misc) + terminus (PCF).
- Client libs in v1: `x11-base/xorg-proto`, `libxcb` (+xcb-proto), `libX11`, `libXext` — AND NOTHING ELSE. No Xt/Xaw/Xmu/ICE/SM.
- Everything cross+static under `configs/portage/env/static.conf`; every source Manifest-pinned; overlay ebuild edits revbump (S3 binpkg cache — see memory `overlay-ebuild-revbump-busts-binpkg-cache`).
- Overlay ebuilds need a `<cat>/<pkg> **` line in `configs/portage/package.accept_keywords/i486`.
- Hand-authored rootfs files (startx, .xinitrc) go into `app-misc/monolith-base` (owned, not allowlisted — see memory `rootfs-files-unowned-attestation`), NOT hand-installed by build-rootfs.sh.
- No display manager, no compositor, no autostart-X, no second GUI stack — ever.
- Honor vesafb's mode (800x600x8); Xfbdev inherits the fb, no modesetting of our own.
- Ground truth (2026-08-14): INPUT_MOUSEDEV=y, MOUSE_PS2=m, SERIO_SERPORT=y (already built-in), KEYBOARD_ATKBD=y, FB_VESA=y, DRM off, gpm in world.

### G1: X-server lane decision + bare Xfbdev boot (RESEARCH-GATED — the pivot)

**Interfaces produced (G2+ consume these):** a working, static, no-dlopen `x11-base/monolith-xserver` providing `Xfbdev` that boots on vesafb; the chosen lane (A/B/C) and its pin (source URL/version + configure line + patches).

- [ ] **Step 1: Recon (IN PROGRESS — background research agent).** Investigate Lane A (maintained tinyx fork), Lane B (pinned xorg-server 1.20-era kdrive-only Xfbdev static, Alpine/sabotage/oasis prior art), Lane C (Xvesa fallback). Output `.batteries/reports/gui-xserver-recon.md` with a decisive lane recommendation + exact pin + configure flags + expected patches + license. → **This gates the rest of G1.**
- [ ] **Step 2: Author `x11-base/monolith-xserver` per the chosen lane.** Overlay ebuild (house pattern: Manifest-pinned tarball + patches in `files/` + `**` accept_keywords). kdrive-only, `--enable-xfbdev` (+ built-in kbd/mouse input), `--disable-*` everything dlopen/Xorg/DRI/GLX. Under static.conf (static, no-pie). Add to world + versions.lock. Ships `/usr/bin/Xfbdev` (or the lane's server binary).
- [ ] **Step 3: Bare-boot proof (TDD gate before any client).** Boot-test: `Xfbdev :0 -fbdev /dev/fb0 &` then `DISPLAY=:0 xsetroot -solid '#3333cc'` (xsetroot is tiny/Xlib-only — or a 10-line XClearArea probe if xsetroot drags deps); QEMU monitor `screendump`; assert the framebuffer is NOT uniformly black and shows the solid color. Proves the SERVER before dwm/st exist. (This is a scoped-down `gui` boot-test; the full golden lands in G3.)
- [ ] **Step 4: Commit.** `feat(gui): x11-base/monolith-xserver (Xfbdev, static, no-dlopen) + bare-boot proof`. Revbump discipline applies to all future edits.

**Note:** Steps 2-4 get bite-sized detail (exact configure line, patch list, boot-test code) once Step 1's recon report lands and the lane is chosen — their content is genuinely lane-dependent, so detailing them now would be speculative.

### G2: Proto/lib stack + st (de-Xft'd) — first real client
Add `xorg-proto`, `libxcb`(+xcb-proto), `libX11`, `libXext` to world (cross+static, verify no Xt/Xaw pulled). `x11-terms/st` via `USE=savedconfig`: pin a suckless **st noxft** patch into `files/`, set config.h to `fixed`/terminus XLFD, strip Xft/fontconfig from config.mk. Boot-test: X + one `st`, screendump → first golden (blessed reference). Deliverable: a terminal on the framebuffer.

### G3: dwm + dmenu + fonts + startx + CI variant — the real desktop
`x11-wm/dwm` + `x11-misc/dmenu` savedconfig de-Xft (pinned noxft patches, `fixed`+terminus XLFD). `media-fonts/font-misc-misc` + `terminus-font` (PCF; verify `mkfontdir`/`fonts.dir` lands + kdrive font path — no font server, no fontconfig). `/usr/bin/startx` + default `.xinitrc` (stop gpm → `Xfbdev` → dwm + one st), owned by `app-misc/monolith-base`. Land the `gui` boot-test variant (32MB, -vga std) with the bar+st golden compare + in-guest `xdpyinfo` exit-0. Deliverable: `startx` → dwm bar + st, CI-gated.

### G4: Serial-mouse path
`inputattach` (linuxconsoletools) → world (static-clean, verify). Doc the liturgy (`inputattach --microsoft /dev/ttyS0 &`, protocol variants) in the GUI doc — startx does NOT auto-run it. gpm coexistence resolved (stop-gpm vs `gpm -R`, choose simplest). PS/2 mouse verified in QEMU `gui` variant; serial verified by operator on iron (testimonial). MOUSE_PS2=m load path confirmed in the module regime.

### G5: Report + release-readiness
`.batteries/reports/gui.md` (house style): binary/tree sizes, RAM actuals at 8/16/32MB (Xfbdev + dwm + st), the lane chosen and why, what xterm would drag in if demanded, the three worst fights. Update the RELEASE-READINESS GUI line.

**Follow-ups (NOT v1):** xterm (compat/nostalgia; drags Xt/Xaw/Xmu/ICE/SM) · Worker file manager (Xlib static) · Window Maker second-act eval · Stele x11 backend rendezvous (Stele speaks raw wire protocol; needs none of this stack except the running server).
